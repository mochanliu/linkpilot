# 控制器 3 节点 HA：部署与运维手册

2026-11-14。面向现场交付与运维。设计依据 [controller-ha-plan.md](controller-ha-plan.md)，本文只回答
"怎么装、怎么判断装对了、坏了怎么办"。所有操作都在控制台完成，**不需要登后台、改配置文件、重启老节点**。

> 一句话：三台控制器组成一个 raft 集群，只有 leader 写、任意节点读，写请求自动 307 到 leader；
> 设备拿的是"控制器地址表 + 当前 leader"，不依赖 VIP，换主时设备不重启、不重新入网。

---

## 0. 先决条件

| 项 | 要求 | 为什么 |
|---|---|---|
| 台数 | **3 台**。2 台不算 HA，4 台不加可用性 | 2 台多数派是 2，倒一台就写不进去；4 台多数派是 3，仍然只容 1 台坏，每次写还多等一台 |
| 地址 | 每台一个**固定 IP**（不要 DHCP 漂移） | 成员表里记的是 host:port，地址变了等于这台失联 |
| 端口 | 控制器之间：`8444/tcp`（mTLS + `X-Cluster-Secret`）；设备 → 控制器：`8444/tcp`；运维 → 控制台：`8443/tcp` | 8444 是 `-listen`，8443 是 `-console`，两个监听器 |
| 互通 | 三台两两可达 8444；每台的控制台地址对运维浏览器可达 | follower 的写要 307 到 leader，浏览器按成员表里的 console 地址跳 |
| 时间 | 建议 NTP，但**不是正确性前提** | 选举用单调时钟；证书有效期与日志时间戳要它 |
| 磁盘 | ≥1 GB 余量给数据目录 | `state.json`（快照）+ `cluster/log.jsonl`（日志）+ 证书 |
| CA | 一套，集群共用（加入时自动分发） | 设备证书、节点证书都要互认；见 §10 的 CA 风险 |

数据目录（`-data` 指的地方）里有这些，**备份就是备份整个目录**：

```
ca.pem  ca.key                集群 CA（开启集群后会被 leader 的统一 CA 覆盖）
server.pem  server.key        本机 TLS 证书（加入后按集群 CA 重签，SAN 覆盖本机地址）
cluster/secret                节点间调用凭证（X-Cluster-Secret）
cluster/node-id              本机成员 id
cluster/meta.json             term / votedFor / commit / applied / 日志基点
cluster/log.jsonl             raft 日志（追加写，fsync 后才应答）
state.json                    已提交的硬状态 = 快照
console-tls/{cert,key}.pem    -console-tls 时才有
```

## 1. 装第一台（这时还是单机）

```bash
install -m 0755 sr-ctrl /usr/local/bin/sr-ctrl
sr-ctrl -data /var/lib/sr-ctrl \
        -listen 0.0.0.0:8444 \
        -console 0.0.0.0:8443 -console-tls -console-san 10.0.0.11 \
        -tls-san 10.0.0.11 \
        -node-name ctrl-1
```

- 不给 `-admin-token` 时它会生成一个并**只打印一次**（也可用 `$SR_CTRL_ADMIN_TOKEN` 注入），抄下来。
- `-tls-san` / `-console-san` 填这台机器**对外**的地址或域名，证书要覆盖它，否则设备与浏览器都不认。
- `-console-tls` 用的是自签证书：第一次打开控制台浏览器会告警，正式交付请用
  `-console-cert` / `-console-key` 换成受信任证书（设备侧认的是集群 CA，与控制台证书无关）。
- **单机模式照旧可用**：不开启集群时它就是原来那台控制器，行为不变。

systemd 单元（三台同款，只有 `-node-name` 与地址不同）：

```ini
[Unit]
Description=SD-WAN controller
After=network-online.target

[Service]
ExecStart=/usr/local/bin/sr-ctrl -data /var/lib/sr-ctrl -listen 0.0.0.0:8444 \
  -console 0.0.0.0:8443 -console-tls -console-san 10.0.0.11 -tls-san 10.0.0.11 \
  -node-name ctrl-1
Restart=always
RestartSec=3
StateDirectory=sr-ctrl
# 注意：这里不要放 -join / -join-token，理由见 §8
```

> `Restart=always` 在"这台被下线"的时候会变成每 3 秒起一次、每次都立刻退出的循环
> （下线的节点起来会自己拒绝启动，见 §5.2）。想干净一点就写 `Restart=on-failure`：
> 崩溃照样拉起，**正常退出（下线）就保持停着**。

## 2. 开启集群

控制台 →「控制器集群」，页面显示**现在这台控制器是 单机**。填三项 → 开启集群：

| 字段 | 填什么 | 注意 |
|---|---|---|
| 本机地址 | `10.0.0.11:8444` | **设备与其它控制器都通过它访问**，必须是 8444 |
| 控制台地址 | `10.0.0.11:8443` | 浏览器访问的地址；follower 的 307 也往这里跳 |
| 名称 | `ctrl-1` | 只给人看，成员表里显示 |

开启之后：这台立刻是 leader（单 voter 集群自选），页面出现成员表、投票成员数 `1`、提交点。

> ⚠️ 这一步是**单向**的：`state.json` 从此就是共识快照，没有"关闭集群"按钮。
> 退回单机只能靠数据目录备份（§7）。**点之前先备份**：
>
> ```bash
> tar -czf /root/sr-ctrl-precluster.tgz -C /var/lib sr-ctrl
> ```

## 3. 加第 2、3 台

在「控制器集群」页填：名称 `ctrl-2`、新机器地址 `10.0.0.12:8444`、它的控制台地址 `10.0.0.12:8443`
→ **生成加入码**。页面会直接给出可复制的命令（这就是"不需要后台部署"的全部含义）：

```bash
sr-ctrl -data /var/lib/sr-ctrl -listen 0.0.0.0:8444 -console 0.0.0.0:8443 \
        -console-tls -console-san 10.0.0.12 -tls-san 10.0.0.12 \
        -node-name ctrl-2 \
        -join https://10.0.0.11:8444 -join-token <加入码>
```

新节点起来后以 **learner** 出现在成员表里（`角色=learner`，`落后` 列显示差多少条），
追上日志后由 leader 每秒检查、连续 3 次追平就**自动提升为 voter** —— 客户不需要再点任何东西。

第 3 台重复一次，把 `ctrl-3` / `10.0.0.13` 填进去。

加入码的规矩：**30 分钟过期、只能用一次**（重复使用会回 409 `这个加入码已经用过了`）。
它里面带着集群 CA 的 PEM，所以新节点拿到的是"和集群同一套信任根"，不是"可以开始了"。

## 4. 验收（五条，缺一条不算交付）

| # | 怎么看 | 通过标准 |
|---|---|---|
| 1 | 成员表 | 三行都是 `voter` + `active`，且**只有一台**是 leader |
| 2 | 三台各自的控制台 | `提交点`（commit）三台一致；本机 `已应用`（applied）≥ 提交点 |
| 3 | 建一个测试租户 → 刷新另外两台 | 两台都能看到（硬状态进了共识） |
| 4 | `kill -9` 掉 leader | 30 s 内出现新 leader；期间写还能提交；打 follower 的地址发写会被自动跳到 leader |
| 5 | 把杀掉的节点原样起回来 | 自动追上日志、身份变成 follower，不再自认为是 leader |

第 4 条的准确口径：选举超时 1.2–2.4 s、心跳 250 ms，**容器里实测新主在 20 s 的断言窗口内一定出现**；
"≤5 s" 是设计目标，真机三台的数字**还没测**（§10）。

## 5. 日常操作

### 5.1 替换一台坏的

适用：某台硬件坏了/盘坏了，换一台新机器顶上（**新机器可以直接用旧机器原来的 IP**）。

1. 成员表里点那台的 **替换**（定下替换目标），填新机器的名称/地址/控制台地址 → 生成加入码；
2. 新机器上跑那条命令；
3. 等两件事自动发生：新成员 `learner → voter`；**旧成员被自动标成 `已下线`**（note 写着"被 ctrl-x 替换"）。

不需要手动下线旧的，也不需要改设备配置 —— 设备在新 leader 上照样拿到地址表。

### 5.2 下线一台（4 台退成 3 台）

成员行点 **下线**，填原因（会进台账）。生效立即：这台不再参与多数派，成员行留着做审计。

**那台机器会自己退场，不需要你去停机**（2026-11-14 起的版本）：

1. 约 1 秒内它自己的控制台集群页变成"本机已被移出集群"，`retired: true`；
2. 设备侧所有接口立刻回 `503` 并带 `X-Cluster-Leader`，设备下一拍就换到别的节点
   （回 200 才是坑：设备会继续往一台已经不该服务的机器心跳）；
3. 10 秒后进程自己退出，日志里两行：`本机已被移出集群（…）` / `已被移出集群，进程退出`。
   要留在现场看，启动时加 `-retire-exit=false` —— 它会照样停共识、照样 503，只是不退。

之后**不要再把它起来**：数据目录里的成员表已经写着它 `decommissioned`，进程会打一行

```
cluster: 本机（c-xxxx）在集群 "cl-xxxx" 里已被移出成员表，不再启动。重新加入请清空数据目录 … 后签一张新的加入码
```

然后退出。`Restart=always` 的单元会因此变成"每 3 秒起一次、立刻退出"的循环，换成
`Restart=on-failure` 即可（见 §1 的单元注释）。

- 剩 2 台仍可写（多数派 2），但**这时已经不算 HA**：再倒一台就只读；
- 最后一台有投票权的成员**不允许**下线（会被拒：`这是最后一台有投票权的控制器`）。

### 5.3 修好的机器想加回来

**先清空它的数据目录**，再按 §3 走新加入码：

```bash
systemctl stop sr-ctrl && rm -rf /var/lib/sr-ctrl/* && systemctl start sr-ctrl   # 然后再用新加入码起
```

原因：下线只是把成员行标成 `decommissioned`，那台机器数据目录里的身份还在，拿它去换新加入码
会被"已经用过了"挡回来。清空后重新加入，硬状态从 leader 的快照重建，**不会因此少数据**。

（如果那台已经在 §5.2 里自己退出了，`systemctl stop` 那句会返回"没在跑"，无害；关键是
`rm -rf` 之后再带新加入码起。）

### 5.4 滚动升级

一次一台，**先 follower、最后 leader**，每台都要等它重新追上再动下一台：

```bash
# 以 ctrl-2 为例（当前是 follower）
systemctl stop sr-ctrl
install -m 0755 sr-ctrl-new /usr/local/bin/sr-ctrl
systemctl start sr-ctrl
# 判据：这台控制台的 applied >= 提交点，成员表里它状态是 active（不要求它是 leader）
```

三台里任何时候至少两台在线 —— 这是换件不会中断写的原因。

## 6. 故障剧本

| 剧本 | 会发生什么 | 控制台看到什么 | 要不要人动手 |
|---|---|---|---|
| **leader 挂 / 断电** | 另两台 1.2–2.4 s 后开始选举，新主接手；旧主回来时自动降为 follower 并追上 | 页头 `有多数派`；本机角色跟着变 | 不用 |
| **两台同时挂**（掉多数派） | 停止接受写，**读与设备心跳照旧**；设备配置不变、转发不受影响 | 页头 `无多数派 · 只读`，写请求被拒（不是"看起来成功"） | 起回任意一台即恢复可写 |
| **一台磁盘坏 / 起不来** | 剩两台继续写；成员表里那台 `失联` | 成员行状态 `失联`，落后持续增长 | 换机走 §5.1 替换 |
| **网络分区（1 对 2）** | 多数的两台照常；落单那台只读，不会出现两个主 | 落单那台 `无多数派 · 只读` | 修网络，落单那台自动追上 |
| **控制台地址打不开**（DNS/VIP 指到挂的那台） | 只是入口问题，集群没事 | — | 直接换另一台的地址；建议 DNS 轮询三台 |
| **设备连不上原来的控制器** | agent 每次心跳拿到地址表 + leader：换主直接切，连不上立刻试下一个，**整张表都失败才退避**（2 s→30 s） | — | 不用 |

一条硬规矩：**掉多数派时不要"重启试试"**。它不会自己变好，起回一台就够了；乱重启只会让日志更难对齐。

## 7. 退回单机（代价写清楚）

没有"关闭集群"这个动作。退回单机的唯一路径是**用开启集群之前的备份恢复**：

```bash
systemctl stop sr-ctrl
rm -rf /var/lib/sr-ctrl && tar -xzf /root/sr-ctrl-precluster.tgz -C /var/lib
systemctl start sr-ctrl      # 起来就是单机，成员表不存在
```

代价：备份点之后的配置、台账、告警全部丢失。所以 §2 那句"点之前先备份"不是客套。

## 8. 不要做的事（现场最容易犯的六个）

1. **只装 2 台**。多数派 2，倒一台就写不进去 —— 卖的时候就要说清，别等交付现场解释。
2. **把 `-join` / `-join-token` 写进 systemd 单元**。加入码一次性，机器一重启就会拿着用过的码重放。
   现在程序会**忽略它并打日志**（`本机已经在集群 … 忽略 -join`），但别依赖这个兜底。
3. **同一个地址加两次**。会被拒（`地址 … 已经是成员 …`）：两个成员共用一个地址会把多数派算虚，
   表现为"加了一台，一直不变投票成员"。要接管旧 IP 请走**替换**。
4. **把 A 的数据目录拷到 B 当"备机"**。两份同样的身份 = 精神分裂：两台都认为自己是一个成员，
   日志会互相覆盖。备机只能用加入码加进来。
5. **在 follower 上用 curl 直接 POST 写**。会拿到 307 而不是结果（浏览器会自动跟，`curl` 不会）：
   要么加 `-L`，要么直接打 leader 的地址。
6. **同时点两次"替换"**。成员变更一次只改一台，第二次会排在同一把锁后面；等第一台变成 voter 再动第二台。

## 9. 现场排查：从症状到第一个该看的地方

| 症状 | 先看 | 常见原因 |
|---|---|---|
| 写请求全部超时 | 页头是 `有多数派` 还是 `无多数派` | 掉多数派（起回一台）；或 leader 正在换 |
| 页面能开、点了没反应 | 本机角色是 follower 且 307 目标不可达 | 成员表里的 console 地址写错了（填了内网地址，浏览器到不了） |
| 新加的机器一直是 learner | 成员行 `落后` 列是否在减少 | 8444 不通 / 证书 SAN 不覆盖它 / 地址填错 |
| 成员表里那台 `失联` | `最后联系` 时间 | 进程挂了、网络断了、或者它在只读（掉多数派） |
| 加机器报"地址已经是成员" | 成员表里谁占着这个地址 | 想接管旧 IP 要走「替换」，不是「新增」 |
| 加机器报"加入码已经用过了" | 那台机器是不是重装过 | 数据目录没清（§5.3） |
| 日志里 `本机不在 voter 集合里` | 成员表里这行的状态 | 它是 learner（正常，等追上），或已被下线 |
| 一台控制器的进程自己没了 | 日志尾部有没有 `已被移出集群，进程退出` | **正常**：它被下线/被替换了（§5.2）。要它回来先清数据目录 |

日志关键词：`cluster:`（成员/加入/下线/提升）、`raft:`（选举/复制/压缩）。两台日志时间对不上时先校时。

## 10. 这份手册还没覆盖的部分（别当成已完成）

- ~~**真机三台的完整演练没做**~~ → **2026-11-14 深夜做完了**：三个 `sr-ctrl` 进程 + 4 台真 CPE，
  开启 → 加入 → 替换 → 下线 → `kill -9` → 重启全过，数字在 `controller-ha-plan.md` §9.6/§9.7
  （切主 2.24s / 带 pre-vote 后 2.45s，设备侧 0.93–4.93s）。
- **设备侧"任意一台都看到同一份在线状态"没有**：`last_seen` 是各节点本地的软状态，设备只跟
  一台控制器说话，另外两台的设备列表看起来就是旧的（`stale`）。**别把 follower 上的"离线"
  当故障**，先看页头的 leader 是谁，再去那一台上看。
- **CA 是三节点共用的**：加入码会把 CA 私钥交给新节点，风险等价于"把 `ca.key` 拷到三台机器"。
  要不要换成"集群根签发、根密钥离线"，还等 owner 拍板（`controller-ha-plan.md` §11-3）。
- **台账/审计还没进共识**（P3）：现在每个节点只查得到自己的台账，所以"从任一节点看全部历史"不成立。
