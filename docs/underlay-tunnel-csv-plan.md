# 隧道表格：一份 CSV 里同时新增、修改、删除（2026-11-14）

owner 需求原话：「underlay 的隧道配置增加一个功能，允许下载表格模板，然后上传表格
进行配置。设计下表格格式，在一个文件里能同时添加删除和修改。」

实现：`controller/cmd/sr-ctrl/underlay_csv.go`（模型+解析+计划+落库）、
`underlay_api.go` 的两个端点、`console.html` 的「表格批量配置」面板、
`underlay_csv_test.go`（十个用例）、`console_nav_test.go`（接线钉住）。

## 1. 为什么是一行一条隧道、而不是一行一个动作

操作者拿到手的文件必须「所见即所得」：下载的是当前隧道表，改完传回来，控制器
把每一行和他看到的隧道对上。所以一行的语义是**「这条隧道应该长这样」**，不是
「执行这个动作」。三件事因此放进同一个文件：

- **新增**：隧道ID 留空；
- **修改**：隧道ID 填着，改想改的单元格（「操作」列可以留空）；
- **删除**：「操作」列写「删除」；或者整行删掉 + 页面勾「以文件为准」，
  文件里没提到的现有隧道一并删除。

「以文件为准」是**显式勾选**（opt-in），不是默认：有人只导两行新增就把全表删了，
那种事故必须发生在操作者看得见的预览里，而不是服务器替他做决定。

## 2. 列（15 列，顺序固定）

定义在 `underlayCSVColumns()`，**只有这一处**：导出表头、上传表头校验、
页面上的格式说明三处共用它，`TestUnderlayCSVHeaderMatchesLegend` 钉住不漂移。

| 列 | 空 = | 备注 |
| --- | --- | --- |
| 操作 | 自动判断 | 新增/修改/删除，也收 add/update/delete |
| 隧道ID | 新增 | 控制器分配；修改/删除必填 |
| 本端设备 | — | 序列号 / `node-3` / `3`；两台同名时该名字不可用（宁报错不二选一） |
| 本端接口 | 设备上报的出口 | |
| 本端地址 | 观测到的外层地址 | `ip` 或 `ip:port` |
| 本端端口 | 自动分配 | 修改行留空 = 保留原端口（不会重分配） |
| 对端…四列 | 同上 | |
| 颜色 | 0 | 0..7 |
| 权重 | 1（默认） | 1..255；开动态时是调度上限 |
| 动态 | 关 | 开/关，也收 on/off/true/false/1/0 |
| FEC | 0（关） | 0..4 |
| 中转路径 | 直连 | `模板:名称` 引用共享模板；`a>b>c` 内联链，每跳 `a` 或 `a@地址`（页面上的「a（地址）」写法也收） |

两个有意为之的不对称：

- **接口/地址/端口留空 = 保留**（这三样没有比"现在这个值"更好的默认），
  **颜色/权重/动态/FEC 留空 = 取默认**（表格里空单元格就是"要默认值"）。
- **单独写一台设备名当路径 = 一跳内联链**（列名是「中转路径」，写一台设备就是
  经过它）；要用共享模板必须写 `模板:名称` 前缀，否则「设备名叫 X」和「模板叫 X」
  无法区分。

## 3. 语义与安全边界

- **先预览后写入，且全有或全无**：`dry=true` 出逐行计划（新增/修改/删除/不变/问题 +
  原因），`dry=false` 在克隆上整套执行、成功才换入。任何一行有错（设备不存在、
  颜色越界、模板找不到、端口冲突）→ 整份拒绝，什么都不写。半份落库之后文件就
  不再描述控制器，这是最难恢复的形状。
- **没改的行是「不变」，不产生写**：逐字段与现有隧道比对（设备名、模板名都先
  归一化再比），原样回传一份文件 = 0 改动，不 bump Gen、不给设备重下发
  （`TestUnderlayCSVRoundTripChangesNothing`）。落库顺序：先删（腾端口与 /32）、
  再改、后增——同一份文件里"删掉一条腾出端口、另一条正好用上"是合法意图。
- **上传走 base64 + JSON**：`requireSession` 规定控制台 POST 必须 JSON（挡跨站
  表单），而 base64 才能让文件字节原样到达——控制器要能对着真实的 GBK 文件说
  「请用 CSV UTF-8 另存」，而不是对着浏览器猜过的乱码说「设备名不存在」。
- **表格只引用模板、不创建模板**：模板的语义是"改一处、全体跟随"，让表格顺手
  建模板会把这种共享关系藏进一张没人看的表里。
- **失效模板不静默变直连**：导出时解析不了的模板写成 `模板:<id>`，回传时报错
  指名这条隧道，而不是把一条中转隧道悄悄压平。
- 上限：2000 行 / 1 MiB（每对设备密钥槽上限 8，两千行已经越过物理上限）。
