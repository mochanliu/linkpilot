# exp-277：把「在跑的那一份」补装到盘上，消除重启即静默退回旧件

对应 `docs/vmlab-rebuild-plan.md` §9.22，收口 `docs/agent-handover.md` §3 记的三只雷（缺陷⑦ #268、缺陷④ #260 的产物侧，加插件盘上那份）。
**本轮一行代码没改**，改的是四台的产物一致性 —— 缺陷本身的修复早在 11-05/11-06 就进了源码（`d949434`、`de156c0`、`051f37e`）。

## 一、要关的是什么

11-06 夜实测：四台的 `sr-fib`、`sr-agent` 两个进程跑的是修复件，而 `/usr/local/bin` 里躺着的是修复前那一份。
后果不是"现在坏"，是**任何一次重启或开机重放都会静默退回坏的那一份**：

- `sr-fib` 退回 `41c04d57…` ⇒ VPP 重启后不重连 `api.sock`、隧道表只在内存 ⇒ 客户流量永久黑洞（缺陷⑦）；
- `sr-agent` 退回 `f2e14612…` ⇒ VPP 重启后不重建 wg 隧道且仍报 `ok=true`（缺陷④）；
- 插件 CPE2/3/4 盘上停在 `9d611883…` ⇒ 下一次重启 VPP 载入的是遥测前那一代（在跑的那代有探针，靠盘上哈希判不出来）。

## 二、做法：盒内复制 `/proc/<pid>/exe`，不走网络

```bash
bash test/lab/vmlab/exp-277/align-disk.sh CPE1 CPE2 CPE3 CPE4
```

每台三步，逐件带哈希闸门（不符就整台中断、不装）：

1. `run = sha256sum /proc/<pid>/exe` 必须等于期望值（`sr-agent d2ad8519…`、`sr-fib bab523ff…`，
   两者都是 Mac 产物树里核对过的那两件 —— 见 `/Users/louis/srvmlab/MANIFEST.md` A 组）。
2. `cp /proc/<pid>/exe /usr/local/bin/<x>.swap` → `chmod 0755` → 旧件留底 `<x>.prerun-20261107` → `mv -f` 换上。
3. 只有插件（247KB，盒上没有那份字节）走一次 HTTP 拉取：`curl http://192.168.1.4:8799/...`，
   拉完在盒上校 `9267d28d…` 才装。

三个"为什么不"，都是这一轮的硬约束：

- **为什么不 kill / 不 restart / 不动 watch timer**：AGENTS.md §1 第 1 条。换盘上文件不需要进程配合，
  正在跑的进程继续持有旧 inode，行为一个字节都没变。
- **为什么不用 `install -m 0755 <src> /usr/local/bin/<x>` 直接覆写**：覆写正在执行的二进制吃 `ETXTBSY`；
  被 mmap 的插件更糟 —— 会把在跑的数据面就地写坏。所以走同目录临时件 + `mv`（同盘 rename，原子）。
  VPP 那边 `grep sr_wg_plugin /proc/<vpp pid>/maps` 显示 `... (deleted)`，说明在跑的那一代已经没有路径名指向它。
- **为什么不走 `push-binary.sh`**：实测 Mac↔盒子这条链路只有 **7KB/s 量级**
  （gzip+scp 的 5.4MB 走了 10 分钟没走完，我把它停了；换成盒子主动 `curl` 247KB 用了 36.29s = 6,817 B/s，两个方向一样慢）。
  四件 18MB 按传输要两个多小时，而传输根本不是必要的 —— 盒内复制是零传输且字节必然等于在跑那一份。

顺带核过一件事，免得 `sr-box-watch.timer`（60s 一轮 `start.sh up`）把我装的覆盖回去：
`grep -nE "install |cp -|mv |artifacts" /usr/local/lib/sr-box/start.sh` **零命中** —— 清单只 `nohup` 起进程，不装二进制；
而它的幂等前提"在跑的进程绝不重启"是 11-05 实测过的。

## 五、这一轮**没有**证明什么（局限，别读过头）

1. **"重启不再退回"是推导，不是实测。** 依据是字节级相同（`run==disk`），我没有为了验证而重启任何进程 ——
   那本身就违反 §1。要实测就走一次受控重启，那是一次有中断的操作，得单独拍。
2. **插件本轮只是把"下一次重启 VPP 载入哪一份"对齐到带探针那一代**，在跑的数据面一个字节没变
   （VPP 只在启动那一刻加载插件）。所以"在跑的是哪一代"仍然只能用功能探针判（`vmlab` 把手 §4 第 3 条）。
3. **开机重放整条链没有在这里验。** 盘上补齐之后，开机时 `sr-fib` 起的是修复件、`sr-agent` 会重建隧道，
   但隧道表在磁盘上恢复不了那一处仍是缺口 G-2（`sr-box.service` 那个 exit 1 是它，不是新的）。
4. **`sr-route` 仍停在 11-04 那一代的内容**（run 与 disk 都是）。把它抬到 HEAD 必须换进程，
   而换进程就撞缺陷⑧（#269 未拍）—— 这是有意留的分叉，不是漏。
