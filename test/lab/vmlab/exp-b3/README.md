# B3 实测：可达性变化到「那条腿从 VPP FIB 摘掉」这一段

对应缺口：**B3 —— watch 模式下隧道/BFD 状态变化没有任何东西触发收敛**
（登记在 `docs/queue-plan-next.md` §三 与 `docs/agent-handover.md` §3 的表里）。
这条不修不许把 sr-route/sr-fib 抬到其余盒。

## 一、这一段到底是哪一段

场景（客户视角）：站点 3 到站点 1 的那条 WG 隧道塌了，但**路由表一个字没变** ——
RR 还在发 `172.16.12.1/32`，本盒 Loc-RIB 里那条前缀还在、还带着 next_hop。

代码按这个场景一步步走到哪：

1. 隧道的真实可达性只有一个来源：本机 VPP 里那条**多跳 BFD 会话**
   （`vppctl show bfd sessions`，Detection Time 150ms = 3 × 50ms）。
2. sr-fib 每一轮收敛才去读它：`cmd/sr-fib/main.go` 的 `converge()` →
   `f.dp.BFDSessions(ctx)` → `fib.UnreachablePeers(sessions)`（`internal/fib/reach.go:20`）→
   `fib.PlanFrom(...)`（`internal/fib/fib.go`：该路径跳过，并登记一条警告）。
3. 所以「BFD 判 down」要变成「FIB 里那条 `mpls via` 消失」，中间隔的是
   **一次收敛被谁叫醒**。#276 之后叫醒它的只有三处：启动/重连时那一次全量、
   sr-route 的 SSE 事件批、`PUT /config`（`cmd/sr-fib/watch.go:296-325` 的 `convergeLoop`
   只 select `f.wake`）。
4. 上面第 1 步和第 2 步之间的这个场景里，三处**一处都不发生**：RIB 没变 ⇒ 没有事件批，
   没人改配置 ⇒ 没有 `PUT /config`，进程活得好好的 ⇒ 没有启动全量。
   于是那条已经死掉的腿一直挂在 FIB 里，ECMP 继续把落在同一个哈希桶里的那条流整条送进去
   （见 §三 最后一条，实测不是丢一半而是这条流全断）。

症状就是这一句：**摘路那一枪要么等下一发路由事件（没有期限），要么靠老轮询那一版的
下一轮 poll（1s 封顶）。**

B3 的修法（owner 已点头，「B3 按你说的」）：sr-fib 订阅 VPP 的 BFD 会话状态事件
（`want_bfd_events` + `bfd_udp_session_event`），状态一翻转就 `signal()`。
事件只当**触发器**，真相仍然由下一轮 `bfd_udp_session_dump` 的全量决定 ——
这是电平触发不是边沿触发，也正是 §1 第 3 条要的：不许用旧集合再撑一拍。

## 二、为什么注入必须在对端做（这一节是这一枪踩出来的，不是先验的）

前两臂都作废过，原因相同：**注入的地点决定了量的是谁。**

- 在被测盒自己 `set interface state wgX down` —— 看着像在测 sr-fib，其实不是。
  本机口一 down，VPP 自己就把经这个口的邻接判死，不等 sr-fib。
  CPE1 那一枪实测：sr-fib 一条日志都没打，`mpls via` 照样从 1 归 0，
  客户探测 1619 发只 FAIL 1 发（2026-11-09 实测）。
  ⇒ 这一形状对 B3 改不改都无差别，量不到这一段。
- 所以故障必须打在**对端**的隧道口上：被测盒的口全程 up，邻接仍然 resolved，
  唯一能把这条腿从 FIB 里拿掉的就只剩 sr-fib。采样器因此必须同时盯本机口态当控制变量，
  整枪出现一次非 up 就整臂作废。

## 三、口径

- 锚点取**被测盒自己采到的 BFD 状态翻转**，不试图跨盒对齐注入命令的时刻：
  这几台盒钟互差 0.8~8.2h（2026-11-09 实测），跨机对齐会把 48ms 量成 480ms。
- 紧采样器在被测盒上，一发三个 `vppctl` fork（BFD 会话 / `show ip fib` 的 `mpls via` 条数 /
  本机隧道口 oper 态），实测分辨率 = 间隔中位 **63ms**（间隔由 fork 数决定，不是 `sleep`）。
- 慢采样器 0.5s 一发，读 sr-route `/status` 里这条前缀在不在、可不可装。
  `mpls via` 变少有两种成因：①sr-fib 因 BFD 非 Up 摘了这条路径（前缀还在、还带 next_hops）；
  ②对端把这条路由撤了（前缀根本没了）。B3 只管①，所以摘路那一段必须配着这一路读，
  rib 全程不翻转才允许把条数变少记到 B3 头上。
- 客户可见 = 探测机上 `ping -I <本机 loopback>` 的 ok/FAIL 分布（自钟自算，只按段读）。
  **`-I` 不能省**：不带源地址的 ping 走的是没有回程的 underlay 源，会量出 100% 丢包，
  与可达性无关（2026-11-09 就是这样误判过一次「BFD 根本没起来」）。
- 多腿前缀才有读头，但**别把「留着死腿」写成丢一半**：VPP 的 ECMP 哈希按流选桶，
  同一组源/目的地址的 ping 落在同一个桶里，所以实测到的是「这条流全断且不自愈」而不是散开的 50%。
  缺陷臂（下面第二节）里故障窗口内 20 发探测全 FAIL；现状臂删掉死腿后同一时刻就恢复了。
  要量出「一半」得开多条并发流，这一枪没开 —— 结论只取「有没有自愈」。

## 四、三臂

三臂只差在被测盒（CPE3）上跑的那一份 sr-fib，锚点、注入、口径完全相同：
前缀 `172.16.12.1/32`（CPE3 有两条腿：经 CPE1 的 `10.250.0.0` 与经 CPE4 的 `10.250.0.6`），
注入 = CPE1 的 `wg1009` 单发 down → 20s → 单发 up，探测 = cust3 `-I 172.16.3.1` → `172.16.12.1`。

| 臂 | 被测盒上跑的 sr-fib | 触发形状 | 摘路 | 装回 | 死腿存活 | 客户可见 |
| --- | --- | --- | --- | --- | --- | --- |
| 现状 | `bab523ff3809f57b` | 每 1s 轮询全量收敛 | **745ms** | **492ms** | 0.82s / 20.30s | 1588 发 FAIL 1 发（0.1%） |
| 缺陷 | `a9f1bc8c8fd49016` + 新 sr-route `26044f78f7969935` | 只被路由事件叫醒 | **无期限**（21s 全程没摘，直到采样结束） | 不适用（腿从未离开） | 死腿在 Down 态的 343 发采样里一直挂 FIB | 871 发 FAIL 20 发（2.3%），连续 20 发覆盖整个 19.92s 窗口 |
| B3 | `c213a6caf1b2aabf` | 路由事件 **+** BFD 会话事件 | **≤65ms**（采样分辨率以下，见下） | **≤65ms** | 0（Down 态 290 发里 ours 一直是 1） | 1557 发 FAIL 1 发（0.1%），无连续断流 |

第一臂的逐时点（同一台盒的钟，可直接相减）：

```
1794182100.322  bfd=Up    ours=2 tun=up     ← 静默基线
1794182113.212  bfd=Down  ours=2 tun=up     ← BFD 判 down（对端注入的 150ms 后），腿还在
1794182113.956  bfd=Down  ours=1 tun=up     ← 745ms 后 sr-fib 把这条腿删掉
1794182133.442  bfd=Init  ours=1 tun=up
1794182133.510  bfd=Up    ours=1 tun=up     ← 会话回到 Up
1794182134.002  bfd=Up    ours=2 tun=up     ← 492ms 后装回
```

「现状」这一臂说明两件事：①轮询版确实有兜底，摘路 1s 封顶；②这 1s 全花在等下一轮 poll，
不是花在算计划或写数据面 —— 事件版把这 745ms 打成 45ms 那一类的时间，必须换成 BFD 事件来触发，
否则同样的 745ms 会变成「没有期限」。

「缺陷」这一臂就是那句「没有期限」的实测（同一台盒的钟，可直接相减）：

```
1794183439.741  bfd=Up    ours=2 tun=up     ← 静默基线最后一发
1794183439.807  bfd=Down  ours=2 tun=up     ← BFD 判 down，从这一发起再没有任何东西叫醒收敛
   …（Down 态里 343 发采样，ours 一直是 2，一条不早不晚）
1794183460.211  bfd=Up    ours=2 tun=up     ← 会话回到 Up，仍然没有东西叫醒收敛
1794183479.028  bfd=Up    ours=2 tun=up     ← 采样结束（后面 19s 也没变过）
```

这一枪跑完之后 `tail /var/log/sr-box/fib.log` 的最新一行仍是补隧道表那次
（`PUT /config：VRF [0]、隧道 3 条` 和它紧跟着的那条收敛），也就是说注入的 20 秒里
sr-fib **一行都没打** —— 进程活着、RIB 没动、收敛没有来源，这就是要修的形状。
客户侧那一串 20 发连续 FAIL 就是这条流被哈希进死腿桶里 20 秒、且没有任何自愈。
脚本在缺陷臂打出的「装回 0ms」不是量到了 0 —— 是腿从未离开过 FIB，`≥起手值` 第一发就成立，
这一格读「不适用」。

「B3」这一臂反过来：脚本打的 0ms 是**真的落在分辨率以下**。采样器一格里同时读 BFD 态和
`mpls via` 条数（两发之间 65ms），改后这一枪 743 发里**没有一个中间态**——

```
1794184002.723  bfd=Up    ours=2 tun=up
1794184002.819  bfd=Down  ours=1 tun=up     ← 同一发里腿已经摘了；摘路 ≤ 65ms
   …（Down 态 290 发，ours 全是 1，一次抖回 2 都没有）
1794184022.830  bfd=Down  ours=1 tun=up
1794184022.903  bfd=Up    ours=2 tun=up     ← 同一发里腿装回来了；装回 ≤ 65ms
```

盒上日志把这段钉在同一秒里（`00:26:42 BFD 10.250.0.0 -> down` 紧接一条
`警告: … 的 BFD 会话不是 Up，该路径跳过` + `收敛 routes+1/-0`；`00:27:02 -> up` 紧接一条收敛），
也就是说唤醒源就是那一条事件帧，中间没有任何轮询节拍。客户侧这一臂 1557 发只 FAIL 1 发。

三臂合起来说明的是同一件事：**摘路这一段从「1s 封顶」变成「65ms 以下」，而中间那一版是「没有期限」**。
所以 B3 不是把 745ms 优化成 45ms 那种锦上添花——#276 之后没有它，这个触发点根本不存在。

**换件这一枪的中断（§1 第 4 条要求点名，2026-11-09 实测）**：把 B3 版装上 CPE3 用的是
`exp-276/swap276.sh CPE3 sr-fib`（SIGTERM → 产品自己的开机清单补回 → 轮询新 pid），
新 pid 830408 起来用时 **1639ms**（含清单里排在它前面那几步），同枪客户侧 75 秒探测
**2790 发 0 FAIL**。留底 `/tmp/b3e-swap2/swap-CPE3-sr-fib.txt`。
也就是说：这一枪的窗口比前面三臂任何一个数字都长，但客户流量没掉 —— 因为进程没死的那条腿
（VPP 里的 FIB 行）一直有效，换件不动数据面。

## 五、复跑

```
cd test/lab/vmlab/exp-b3
WORK=/tmp/b3e-<臂名> bash b3-window.sh CPE3 172.16.12.1/32 10.250.0.0 cust3 172.16.3.1 CPE1 wg1009 20
```

签名：`[BOX] [PFX] [PEER] [PB] [SRC] [PEERBOX] [PEERTUN] [DOWN秒]`。
本机隧道口名不手写 —— 从被测盒 `sr-fib :19011/status` 的隧道表按 `next_hop == PEER` 反查，
查不到就直接退出（写错就白测一臂）。

**这一枪会动 lab 状态**：在 `PEERBOX` 上对 `PEERTUN` 各一次 down / 一次 up，单发不循环
（2026-11-08 曾因守卫比对了两种拼写把同一个口抖了 40 次）。动之前先在日常会话里声明窗口。

换过被测盒的 sr-fib 之后，**先补隧道表再开这一枪**，否则三臂都会作废：新进程内存里是 `0 条隧道`，
所有远端路径按「下一跳不在隧道表里」跳过，`mpls via` 条数不变是 VPP 里那些孤儿行还在，
读出来的"摘路/装回"跟 B3 没关系。补法只有一条合法路径 ——
`bash test/lab/vmlab/vm-fib-sync.sh 3`（判据：`隧道 3 条 … converged=True` 且没有 `警告:`）。
`vm-console.py` 报 `401 invalid username or password` 时按 `docs/agent-handover.md` §11 那条走
（运营方令牌 → `POST /api/accounts/reset` → 写回 `~/srvmlab/state/credentials.json`），别改脚本、别猜口令。
